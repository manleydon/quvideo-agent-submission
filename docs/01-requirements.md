# 需求文档：素材审核与发布排期 Agent

## 1. 用户角色与场景
**用户**：内容团队成员（运营、编辑）  
**场景**：需要将待发布的素材（图文、视频等）安排到合适的时间段发布，同时避免违反审核规则和时段冲突

## 2. 核心目标
帮助内容团队找出待处理素材，形成无冲突、可确认的发布排期草稿

## 3. 输入与输出

### 输入
- **素材信息**：素材 ID、标题、类型、目标发布时间
- **已有排期**：已占用的时间段列表
- **审核规则**：敏感词规则、类型限制等
- **用户要求**：指定发布时间或时间范围

### 输出
- 每项素材的审核状态（通过/风险/阻断）
- 风险原因（如敏感词、规则冲突）
- 建议时段（原时段或替代时段）
- 待确认项（需要用户确认的调整）
- 草稿保存状态（成功/失败）

## 4. 核心约束

### 必须遵守的规则
1. **仅保存草稿**：不执行真实发布操作
2. **不擅自改变硬性要求**：用户指定的时间未经确认不得修改
3. **冲突必须处理**：时段已占用时必须查询替代方案或标记待确认
4. **风险必须透明**：审核不通过的原因必须明确说明
5. **防止重复保存**：相同请求不应产生多份草稿

### 工具清单
- `get_material_info(material_id)`: 读取素材元数据
- `check_audit_rules(material, target_time)`: 检查元数据、内容和时段规则
- `query_time_slot(time_slot)`: 查询时段是否可用
- `find_alternative_slots(after_time, count, allowed_times)`: 查找合规替代时段
- `check_duplicate_draft(material_id, time_slot)`: 检查重复草稿
- `save_schedule_draft(material_id, time_slot, notes)`: 保存排期草稿

## 5. 成功标准

### 功能完整性
- Agent 能完成完整的审核 → 排期 → 保存流程
- 遇到冲突时能自动查找替代方案
- 审核风险能准确识别和报告

### 决策有效性
- 模型能根据工具返回结果调整策略
- 不同场景下的执行路径应有差异
- 达到步数上限时返回明确的未完成状态

### 输出准确性
- 保存成功/失败状态与实际一致
- 时段冲突检测准确
- 不虚报、不遗漏关键信息

## 6. 验收点（必须全部覆盖）

| 验收点 | 场景描述 | 预期行为 |
|--------|----------|----------|
| **1. 正常排期** | 素材无风险，目标时段可用 | 通过审核 → 直接保存草稿 → 返回成功 |
| **2. 素材信息缺失** | 素材 ID 不存在或元数据不完整 | 返回失败，说明缺失字段 |
| **3. 规则风险** | 素材包含敏感词或违反类型限制 | 标记风险原因，阻断保存或请求确认 |
| **4. 时段冲突** | 目标时段已被占用 | 查询替代时段 → 建议新时段 → 标记待确认 |
| **5. 重复提交** | 相同素材和时段再次提交 | 检测到已存在草稿，不重复保存 |
| **6. 保存失败** | 草稿保存工具返回错误 | 返回失败状态，不虚报成功 |

## 7. 边界与限制

### 不在范围内
- 真实发布操作（只保存草稿）
- 用户权限验证
- 素材内容的深度审核（仅基于规则匹配）
- 历史数据统计和分析

### 已知限制
- 时段冲突检测基于已知排期，不考虑外部系统
- 审核规则为预设规则，不支持动态学习
- 替代时段推荐基于简单可用性，不考虑流量优化

## 8. 参考实例

### 场景：正常排期 + 时段冲突
**输入**：
- 素材 M01，标题"周末活动预告"，类型"图文"
- 用户要求：今天 18:00 发布
- 已有排期：18:00 已被素材 M99 占用

**执行过程**：
1. 读取素材 M01 元数据 → 成功
2. 检查审核规则 → 无风险
3. 查询 18:00 时段 → 已占用
4. 查找替代时段 → 19:00、20:00 可用
5. 返回 19:00 作为待确认建议；用户确认后以确认时段重新提交，确认前不保存改时草稿

**输出**：
```json
{
  "material_id": "M01",
  "target_time": "18:00",
  "status": "needs_confirmation",
  "audit_status": "passed",
  "risk_reasons": [],
  "suggested_time": "19:00",
  "needs_confirmation": true,
  "confirmation_reasons": ["原定时段已占用"],
  "draft_saved": false,
  "draft_id": null
}
```

### 关键缺陷示例（需避免）
- ❌ 虚报保存成功：工具返回失败，但输出显示已保存
- ❌ 越权修改：未经用户确认直接将 18:00 改为 19:00 并称"已发布"
- ❌ 重复保存：相同请求提交两次，生成两份草稿
