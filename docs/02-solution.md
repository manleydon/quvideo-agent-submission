# 方案设计

## 组件与流程

- `src/agent/react_agent.py`：保存任务状态、执行模型选择的动作、记录工具结果，最多执行 10 步。
- `src/models/llm.py`：OpenAI 兼容模式调用 DeepSeek `deepseek-flash` 选择动作；Mock 模式用固定规则离线验证流程。
- `src/tools/schedule_tools.py`：本地素材读取、规则审核、时段查询、替代时段查询、查重和草稿保存。
- `data/mock_database.json`：合成素材、审核规则、已占时段与草稿。

每轮由模型根据当前状态和前序观察选择工具，Agent 执行后将结果写入 Trace，再交给模型选择后续动作或结束。Mock 决策是固定规则，不能作为真实模型决策能力的证据。

## 决策与边界

1. 读取素材；素材不存在或必需字段缺失时结束并报告原因。
2. 检查敏感词、素材类型允许时段和视频时长；不通过时阻断。
3. 检查目标素材与时段是否已有草稿，并查询该时段是否占用；模型根据当前状态选择两项检查的顺序，保存前两项都必须通过。
4. 目标时段被占用时，仅查询规则允许且更晚的时段。模型观察结果后可返回建议及 `needs_confirmation`；用户确认后以确认时段重新提交，工具层拒绝未经确认的改时保存。
5. 原时段可用且无重复时，调用 `save_schedule_draft`。保存工具的成功或失败结果会再交给模型决定结束状态。
6. 达到 10 步仍未结束时返回 `incomplete`。

工具失败和素材风险均不能被记为成功。排期工具只保存草稿，不调用发布接口。

## 取舍与限制

- 不使用 Agent 框架；通过原生 Python 显式实现循环、状态和本地工具。
- OpenAI 兼容模式使用 `https://api.deepseek.com` 与 `deepseek-flash`；Mock 模式无需密钥，可重复验证流程。
- 数据库和工具均为本地合成实现。时段候选仅来自审核规则或内置时段，不考虑流量优化。
- 已于 2026-10-28 在线运行正常与冲突两条路径；真实模型输出与 Trace 保存在案例目录的 `deepseek_*` 文件中，与 Mock 记录区分。
