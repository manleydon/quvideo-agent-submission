# 项目复盘

## 投入与完成情况

- 实际用时：约 3 小时。
- 已完成：素材读取、审核、时段检查、替代建议、重复检查和草稿保存；六个验收场景均有输入、输出和 Trace。
- 未完成：真实模型的工具失败与异常输出评估；接入真实素材库、排期服务或发布系统。

## 最难的问题

最难的是区分“执行工具的循环”与“模型根据观察结果改变动作”。Agent 每轮都把状态和工具结果交给模型；Mock 用固定规则复现分支，只证明流程和状态处理。两条 DeepSeek Trace 分别覆盖保存成功和时段冲突后请求确认，不能据此推断真实模型在工具失败时也会正确调整。

另一个易错点是确认边界：占用时段后可以提出合规替代时段，但改变硬性发布时间前必须等待用户确认。保存工具还要检查审核通过、无重复且目标时段可用，避免模型输出直接越过业务约束。

## 学习与下一步

这次实现让我更清楚地认识到，Agent 的可靠性依赖显式状态、工具结果和可验证的业务约束。测试应检查最终状态之外的动作序列和副作用，例如替代时段未确认时没有保存、重复提交仍只有一份草稿。

下一步优先为真实模型增加工具失败和异常响应评估，再考虑并发下的幂等保存和更完整的时间/时区校验。当前数据、规则和工具均为本地合成实现，不适用于真实发布流程。
